# Plan for version 2.4.0

## feature:

- 起点和终点处淡入淡出：曲库里的长录音从起点（或续播的位置）开始时淡入，放到终点时淡出，
  和 2.3.0 片段之间的切换一样不再生硬
- 一键在当前位置设起点 / 终点：曲库里按 `(` / `)`，不用先加跳转点再打开面板

状态：已实现并合并（PR #13），随 2.4.0 发布；和计划不同的地方见第 10 节

### 1. 目标

两项都接着 2.3.0，继续为睡前闭着眼听：

- 2.3.0 让播放列表里截在中间的片段淡出淡入，但曲库播放没有变：设了起点的录音从起点突然出声，
  放到终点被一刀切断，再接下一首。顺序播放、单曲循环时，这正是快睡着时最容易被惊醒的地方。
- 设起点终点现在要三步：`b` 加跳转点，`B` 打开面板，选中它按 `s` / `S`。听到正片开始、
  片尾开始时最想立刻按一下，三步太多，闭着眼也不好找光标。

### 2. 用户决定（2026-10-17）

1. **范围**：这一版只做这两项。读文件内嵌章节调研过，这一版不做，调研结果记在第 8 节。
2. **沿用 `clip-fade`**：起点终点处的淡入淡出和片段用同一个设置、同一条曲线，不加新设置。
   2.3.0 刚发布，已经生成的配置文件里有这一行，改名会让它们失效。
3. **按键**：`(` 设起点，`)` 设终点，像括号把想听的那一段括起来。面板里的 `s` / `S` 不变。

### 3. 起点和终点处的淡入淡出

#### 什么时候淡

只对曲库播放（`Origin::Library`，包括队列里的插播）：

- **淡出**：有终点，位置在终点之前、离终点不到淡出时长时。
  - 越过了终点（往后跳到终点或终点之后，一直放到文件结尾）不淡出。
  - 文件结尾不淡出：录音本来就在那里结束，和 2.3.0 片段的规则一样。
- **淡入**：装载时没有从 0:00 开始：
  - 从起点开始（`Opening::StartPoint`）；
  - 从记下的位置继续（`Opening::Resume`）。这里声音同样是从中间突然开始的，有没有起点都一样；
  - 启动时恢复上次的位置（会话恢复），按空格开始放时淡入。
  - 从 0:00 开始不淡入。从起点或记下的位置装载失败、退回 0:00 时也不淡入。
- **淡入只在刚装载之后**：位置一离开 [开始的位置, 开始的位置 + 淡入时长) 就结束，这一遍不再淡入。
  - 一路放过起点不淡入（例如按两次 `0` 从 0:00 放）：这里声音没有被切断。
  - `0` 回到起点、`{` `}` 跳到起点和其他跳转都不淡入，和现在曲库里的跳转一样。
  - 和片段不同：片段开头之前不是这一条的内容，回到开头就是回到切口，所以片段按位置淡入；
    录音起点之前还能放，所以这里跟着装载走。
  - 暂停时停在当时的音量，继续放时接着淡。
- **设起点终点本身不改变音量**：在当前位置设起点不会突然变成无声再淡入；
  在当前位置设终点时已经在终点上，不淡出（见第 4 节）。
- 播放列表的条目照 2.3.0 的规则，不用录音的起点终点。

#### 怎么淡

- 时长和曲线和片段相同：
  - 淡出 `clip-fade` 秒，增益 = (离终点的剩余 / 淡出时长)²；
  - 淡入用它的三分之一，增益 = (已放 / 淡入时长)²。
- 很短的一段：
  - 淡出不超过 [起点（没有时是 0:00）, 终点] 的一半；
  - 淡入不超过 [开始的位置, 终点（没有时是时长）] 的一半。
- **还是 `fade.rs` 里片段的那一份增益**，不加第三份：曲库播放时按起点终点算，放条目时按条目算。
  和睡眠定时的那一份取较小的，“本条”定时和终点淡出一起时只降不回升。
- **装载时先设好增益再开始放**（和 BUG-011 的修复同一个顺序）：
  - 暂停着装载；装载成功后按实际开始的位置设初始增益：曲库播放不从 0:00 开始的是 0，其余是 1；
    再开始放。现在的 `starting_clip_gain(origin)` 在装载前算，改成装载后按开始的位置算，
    退回 0:00 时才不会先静音一下再突然变响。
  - 装载失败时增益不变，还在放的那一条照常。
- 淡入从哪里开始记在播放状态里（例如 `fade_in_from: Option<Duration>`）：
  - 装载成功（以及会话恢复）时设上；
  - tick 里位置离开淡入那一段时清掉；
  - 换曲目、停止时清掉。
- 终点改了（面板的 `s` / `S` / `d`、新的 `)`）之后，下一个 tick 按新的终点算。
  在面板里把前面 1 秒处的跳转点设为终点，音量会直接落到曲线上对应的值；这是手动操作，不另做处理。

#### 设置

- 仍是 `playback { clip-fade 3 }`，含义扩大为“声音被截断的地方”：
  片段的切口，以及曲库里录音的终点、起点和续播的位置。0 同时关掉这些淡入淡出。
- 新生成的 `config.kdl` 改写这一项的说明；已有配置文件里的说明不动，程序不改写用户的文件。
- 读取、检查和默认值都不变。

### 4. 一键设起点 / 终点

#### 按键

| 按键 | 操作 |
|---|---|
| `(` | 在当前位置设起点；已经是起点时取消 |
| `)` | 在当前位置设终点；已经是终点时取消 |

- 只在曲库主界面，和 `b`、`B`、`{`、`}` 一样。跳转点面板里仍用 `s` / `S` 改选中的那一个。
- 搜索框和其他输入框里 `(`、`)` 照旧是输入。

#### 行为

- 能用的条件：
  - 和 `b` 一样：正在播放或暂停中、10 分钟以上的录音；
  - 和 `s` / `S` 一样：放播放列表的条目时不能设，提示
    “播放列表里不用录音的起点和终点，从曲库播放时再设”。
- 位置按文件时间。曲库播放时显示的时间就是文件时间。
- **当前位置 1 秒（`SAME_SPOT`）以内已有跳转点**：对它做 `s` / `S` 的操作。
  - 不是这个角色就设上，名字不变；已经是了就取消，变回普通跳转点，不删除。
  - 两边各有一个不到 1 秒的跳转点时，用离当前位置近的那个，一样近时用前面的。
- **没有**：在当前位置加一个跳转点，同时设为起点或终点。
- 检查和 `s` / `S` 相同：起点要在终点之前，终点要在起点之后、在 0:00 之后。
  - 检查不过时什么也不改：不加跳转点，也不动原来的起点终点。
  - 提示照用现在的：“起点要在终点 … 之前”“终点要在起点 … 之后”“终点要在 0:00 之后”。
- 原来另有起点（终点）时，它变回普通跳转点，留在原处，和 `s` / `S` 一样。
- 跳转点文件只读、路径不是 UTF-8 时，和 `b` 一样提示原因。
- 加点和改角色一次写盘。设完调用 `apply_stop`，终点交给播放器。
- 提示：
  - 设上时照用 `s` / `S` 的说法，例如“已设为起点 1:30，以后从头播放时从这里开始”。
  - 换下了原来的起点（终点）时，后面加上“（原来的起点 0:45 留作普通跳转点）”。
    面板里看得见角色的变化，按 `(` / `)` 时看不见，所以要说出来。
  - 取消时照用“已取消起点，以后从 0:00 开始”“已取消终点，以后播到文件结尾”。
- **这一遍会怎样**：
  - 设起点不跳转，也不改音量（见第 3 节）。
  - 设终点时已经在终点上：播放器只在一路播到终点时停，这一遍会一直放到文件结尾，
    以后从头放时才在这里停。提示里的“以后播到这里就算播完”已经说明了。
  - 收听进度照现有规则：位置在终点前 3 秒以内就记为听完，下次从起点开始；
    刚设的起点后 3 秒以内算还没开始。

#### 实现

- `MarkStore` 加一个按位置改角色的方法（例如 `toggle_role_at(track, position, role, duration)`）：
  - 在复制出来的跳转点里找 1 秒以内最近的那个，没有就按位置插入一个新的；
  - 角色的检查和改动和 `toggle_role` 共用，从中抽出一个对跳转点列表和下标操作的函数；
  - 检查过了才 `entries.set`，所以检查不过时不会留下新加的跳转点；
  - 先检查只读和非 UTF-8 路径；
  - 返回改动的结果：新的角色、原来的角色、跳转点的位置、是不是新加的，以及被换下的那一个的位置。
- App：`Action::ToggleRoleHere(Role)`，在 `src/app/marks.rs` 里和 `toggle_selected_mark_role` 放在一起，
  提示的说法和它共用。

### 6. 实现步骤

每步单独提交。提交前在 dev-fedora 容器中通过 `cargo fmt --all -- --check`、
`cargo clippy --all-targets --locked -- -D warnings` 和 `cargo test --all-targets --locked`。

1. **起点和终点处的淡入淡出**（`src/app/fade.rs`、`playback.rs`、`session.rs`、`state.rs`）：
   - 曲库播放的增益：终点前淡出；装载后记下淡入的开始，离开那一段就清掉。
   - 装载后按开始的位置设初始增益；会话恢复同样处理。

   - 纯函数的单元测试（和 `clip_gain` 的测试并列）：终点前 1.5 秒是 0.25；越过终点、没有终点、
     文件结尾都是 1；很短的一段各不超过一半；`clip-fade 0` 不淡。
   - 用 `player::fake` 测：
     - 从起点装载、从记下的位置继续时，开始放的那一刻增益是 0，放过淡入时长后是 1；

     - 在当前位置设起点、设终点后增益不变；
     - 单曲循环：终点淡出后从起点重新开始，又从 0 淡入；
     - 和睡眠定时“本条”一起时取较小的；
     - 会话恢复到中间位置：按空格开始放时从 0 淡入；

   - 测试：没有跳转点时新加并设上；1 秒以内已有时改它、不新加、名字不变；已是这个角色时取消；
     两边都有时取近的；换下原来的起点终点；检查不过时什么都不改、不留下新点；只读；非 UTF-8 路径；

     - 按键：曲库里 `(` / `)` 对应这两个动作，搜索框里是输入；

### 7. 验收

用户在自己的 kitty 中，用隔离的 XDG 目录打开 `~/Music`：

- **一键设起点终点**：
  - 播放一个长录音，听到正片开始时按 `(`：提示设了起点；`B` 面板里那个位置是起点。
  - 片尾开始时按 `)`：提示设了终点；这一遍继续放到文件结尾。
  - 在已有跳转点上按 `(`：用那个跳转点，不多出一个；再按一次取消。
  - 在终点之后按 `(`：提示起点要在终点之前，什么也没改。
- **起点终点淡入淡出**：
  - 重新打开这个录音：从起点 1 秒淡入，没有咔哒声。
  - 往后拖到终点前十几秒：终点前 3 秒淡出，然后接下一首或停止；下一首的开头不受影响。
  - 单曲循环：终点淡出后从起点淡入。
  - 听到一半退出再打开：从记下的位置淡入。
  - 按两次 `0` 从 0:00 放过起点：音量不变。
  - `config.kdl` 里写 `clip-fade 0` 后都不再淡。
- 2.3.0 还没验的两项一起验：片段切换的淡出淡入听起来有没有台阶感；
  Windows Terminal 里往粘贴框粘贴多行时间轴（有条件时）。

### 8. 这一版不做

- **读文件内嵌章节**。调研结果留作以后参考：
  - MP3 的 ID3v2 `CHAP`：Lofty 0.25 能解析（`Frame::Chapter`，毫秒时间和 `title()`），
    要通过 `Id3v2Tag` 读，通用的 `Tag` 会丢掉章节。
  - OGG / FLAC 里 `CHAPTER001=00:01:02.000`、`CHAPTER001NAME=…` 这样的注释：Lofty 能读到，自己解析即可。
  - FLAC 的 `CUESHEET`：Symphonia 能读（`FormatReader::cues()`），但没有标题，
    还要把 Symphonia 加成直接依赖。
  - M4A / M4B 章节：两个库都不支持，要自己解析；`.m4b` 也还不在曲库的扩展名里。
  - 有章节的多是有声书、播客和混音，ASMR 很少。做的话打算用粘贴框：把章节填成时间轴，
    看过识别结果再 `Ctrl+S`。
- 跳转之后淡入：曲库里的跳转照旧立刻出声。
- 把增益渐变放进音频线程：先用 tick，验收时听出台阶感再做（同 2.3.0）。
- 在跳转点面板里也用 `(` / `)`；连按微调起点终点的位置。
- 2.2.0 之后讨论过的其他想法：耳机和锁屏的上一首 / 下一首在跳转点之间切换；播放列表的改名、复制、
  导入导出和把片段排进队列；响度均衡。

### 10. 实现记录

四个提交依次对应第 6 节第 1–4 步。和上面的计划不同或计划没写到的地方：

- **淡入的开始和结束**（第 1 步）：
  - `load_track` 不再收调用方算好的增益，改收这一项的来源：装载成功后先按实际开始的位置设
    `fade_in_from`，再算初始增益，然后才开始放。曲库播放的初始增益在要淡入时是 0（`clip-fade 0` 时是 1），
    准确的值由下一个 tick 按位置算。
  - 会话恢复设好 `fade_in_from` 后马上算一次增益，暂停着就已经是 0；片段的恢复也顺带在这时设好，
    不再等第一个 tick。会话恢复对所有曲目都恢复位置，所以从中间恢复的普通歌曲按空格后也淡入。
  - 停止时在 tick 里结束淡入，不在各个停止的地方分别清。
  - Rodio 后端装载到某个位置后报告的位置不会早于它，所以“离开淡入那一段”的下界不用留余量。
- **测试用的假后端**加了 `shorten_file`：文件被剪短后，从那之后的位置装载失败，用来测从起点装载不成、
  退回 0:00 时不淡入。
- **按位置改角色**（第 2 步）：
  - `RoleChange` 加了 `replaced`（被换下的那个起点或终点的位置），面板不用，`(` / `)` 的提示用。
  - 只读和非 UTF-8 路径作为 `RoleError` 的两个新值，只有 `toggle_role_at` 会给出，没有另起一个错误类型。
  - 返回的是跳转点的下标而不是位置：提示里要带上已有跳转点的名字。
  - 只在时长以内的跳转点里找 1 秒以内的那个；当前位置在时长之外时什么也不改，也不提示。
  - 面板里 `s` / `S` 的提示和检查不过时的说法分别抽成 `role_message` 和 `role_refusal`，`(` / `)` 共用。
- **1 秒以内的跳转点在当前位置之后时**（第 3 步）：按 `)` 用的是它，终点就在当前位置之后不到 1 秒：
  这一遍会播到它停下，音量也直接落到淡出曲线上对应的值，和第 3 节里在面板中设前面 1 秒处的终点一样。
  第 4 节“这一遍会一直放到文件结尾”只在用的是当前位置或之前的跳转点（包括新加的）时成立。
- **跳转后不到 1 秒就到终点时**：Rodio 后端在跳转后最多 1 秒内用估计的位置，估计跑在声音前面时，
  到终点前最后一点可能已经按“越过终点”算，增益回到 1。只在跳到终点前不到 1 秒时可能发生；
  睡眠定时“本条”按终点淡出时本来也是这样，验收时留意。
- **文档**：README 的按键表把 `Q` 和 `P` 并成一格，给 `(` / `)` 腾出一行；手册页 KEYS 加了 `( , )`，
  `B` 下面加了一段起点终点处的淡入淡出，PLAYLISTS 里“曲库播放不淡”改掉。
- **审查后修的两处**（2026-10-18，见 `docs/known_issues.md`）：
