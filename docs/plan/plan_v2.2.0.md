# Plan for version 2.2.0

## feature:

- 片段播放列表：播放列表的条目可以是整首，也可以是一个长录音里的一段（片段）。从播放列表播放时，
  列表就是播放范围，顺序、循环和随机都在列表里进行，每个列表各记自己的循环方式
- 编辑播放列表：在跳转点面板把一段加进播放列表；列表里可以移动条目、改名、改片段的开头和结尾
- 修复 BUG-010（播放列表写盘失败后，内存和文件不一致）

## 片段播放列表

状态：已实现并合并（PR #6），随 2.2.0 发布；和计划不同的地方见第 16 节
来源：`clip_playlists_feasibility.md` 第 5 节的第 2、3 步。第 1 步（单个录音的起点和终点）已经按
`plan_v2.1.0.md` 实现。报告第 1 节已定的设计（第 1–12 项）这里不再说理由，只落实到交互和代码上；
和报告不同的地方在文中注明

### 1. 目标

ASMR 长录音里常有几段特别喜欢的，比如某一段掏耳、某一段耳语。现在播放列表只能装整首，
播放时还得用跳转点找过去。这一版让播放列表直接装“一段”：把几个录音里喜欢的段落排成一个列表，
睡前从头放到尾，每段放完自动接下一段。

### 2. 用户决定（2026-10-17）

报告没有定下面几项，用户确认按下面的写法做，后文都已按此写好。

1. **发布**：2.1.0 不单独发布。`[Unreleased]` 里已有的跳转点、起点和终点，和这一版一起作为 2.2.0 发布。
   这样在发布之前，`marks.json` 和播放列表 v2 都还能改，不用考虑兼容。
2. **队列只放整首**：`a` / `A` 照旧把曲库里的整首排进队列，这一版不做“把片段排进队列”。
   队列里的整首按曲库的规则播放：用录音的起点和终点，照常续播、记收听进度。
3. **片段播放时的跳转点**：面板、进度条、`{` / `}` 只用片段以内的跳转点，时间按片段内的时间显示；
   `b` 照常可用。在播放列表范围里，面板的 `s` / `S`（设录音的起点和终点）不可用，按了只提示原因。
   列表里本来就不用录音的起点和终点，面板显示的又是片段内的时间，在这里设容易设错。
4. **加片段的按键**：在跳转点面板里选中一个跳转点按 `a`，从它到下一个跳转点的这一段加进播放列表，
   接着弹出列表让你选加到哪个列表。
5. **改片段的开头和结尾**：在列表条目面板里按 `s` 改开头、按 `S` 改结尾，弹出这个文件的跳转点让你挑。
   和跳转点面板里 `s` / `S` 管起点 / 终点一致。
6. **同一首整首加两次**：允许，提示“列表里已有这首，现在有 2 条”。报告说同一个文件可以出现多次，
   主要是为了片段；整首重复多半是误操作，所以提示一句，但不拦。

### 3. 概念

- **播放项**：正在播放的那一项，有两种来源。
  - 来自曲库，包括从曲库排进队列的插播：播放整个文件，按录音的起点、终点和收听进度播放。
  - 来自播放列表：播放列表里的一条，只按这一条自己的范围播放。
- **条目的范围**：条目的开头和结尾。
  - 整首条目从 0:00 放到文件结尾。
  - 片段从 `start_ms` 放到 `end_ms`；没有 `end_ms` 时放到文件结尾。
- **播放范围**：曲库（含文件夹筛选），或者某一个播放列表。`n`、自然播完、循环和随机都在当前播放范围里走。
  队列里的插播不改变播放范围。
- **显示时间**：界面和系统媒体控制看到的位置和时长，等于文件时间减去条目的开头。
  - 曲库播放和整首条目从 0:00 开始，显示时间就是文件时间。
  - 播放器、跳转点、歌词和收听进度一律用文件时间，换算只在 App 里做。
- **当前条目**：列表范围里正在播放（或刚放完）的那一条。它用内存里的编号来认，所以列表增删、
  移动条目之后，还能找到它。

### 4. 播放列表文件 v2

```json
{
  "version": 2,
  "name": "睡前",
  "repeat": "none",
  "entries": [
    {
      "path": "/home/tyzq/Music/ASMR(Rica)/A.m4a",
      "file_size": 123456789,
      "modified_ns": 1760000000000000000,
      "start_ms": 750000,
      "end_ms": 1820500,
      "name": "掏耳"
    },
    { "path": "/home/tyzq/Music/Music/C.flac", "file_size": 2345678, "modified_ns": 1760000000000000000 }
  ]
}
```

#### 字段

- `repeat`：这个列表的循环方式，取值和配置文件相同（`stop` / `none` / `all` / `one`），默认是 `none`，
  即按顺序播完整个列表后停止。
- `path`：必填。路径不是 UTF-8 时 JSON 存不了；加入这样的文件时提示
  “文件路径含有无法保存的字符，不能加进播放列表”。
- `file_size`、`modified_ns`：用来跟随改名（第 9 节）。从 v1 转来的条目没有这两项，
  第一次扫描到这个文件时补上。
- `start_ms`、`end_ms`、`name`：只有片段有 `start_ms` 和 `end_ms`；`name` 整首也可以有。
  - 没有 `start_ms` 的从 0:00 开始，没有 `end_ms` 的放到文件结尾。
  - 读文件时，`end_ms` 不在 `start_ms` 之后的（多半是手改坏的），去掉 `end_ms`，放到文件结尾。
    这和跳转点“终点不在起点之后时去掉终点”的规则一致。
- 同一个文件可以出现多次。

内存里给每个列表和每个条目各一个编号，不写盘。播放范围和当前条目都按编号认。

#### 版本

- 读到 v1：转成整首条目，循环方式用 `none`。原文件先不动，第一次改动这个列表时写成 v2，
  包括在列表范围里按 `z`。没改过的 v1 列表，2.0.0 还能照常读。
- 2.0.0 读到 v2：提示无法读取并跳过，这是 2.0.0 现有的行为，它不会改写这个文件。
  但在 2.0.0 里新建同名列表会覆盖它。这是 2.0.0 的问题，只在降级时会遇到，写进 changelog 提醒。
- 读到比 2 新的版本：提示“版本不受支持”并跳过。文件留在原处、不改名，因为那是新版本的列表。

#### 读不了的文件

- 内容用不了（不是 UTF-8、不是 JSON、缺字段）：改名保留为 `<原名>.json.corrupt-<纳秒>`，从列表里去掉，
  并提示一句。这和收听进度、跳转点的做法一样，复用 `file_records` 里的改名保留。
  改名后扩展名不再是 `.json`，下次启动不会再读到它。
- 文件读不了（权限、磁盘出错），或者没能改名保留：留在原处，并提示。
- 新建列表时，如果按名字算出的文件已经存在，就不新建，并提示：
  “已有同名的播放列表文件 …，但读不了；请先处理它”。这里的文件包括上面留在原处的，
  也包括别的版本的列表。现在的做法是直接覆盖。

#### 写盘（修复 BUG-010）

- 改动先改内存，再写盘。写不了时提示“已改动，但没能保存：…；下次改动或退出时再试”，并把这个列表记为没存上。
  之后任何一次列表改动都连同它一起再写，退出时也再写一次。这和跳转点的做法一样。
- 内存里的改动不撤回，所以重试不会被“已经在列表中”挡住（v2 允许重复，这个检查也没有了）。
  提示里写明已经改了，免得用户再加一次。

### 5. 列表范围里的播放

#### 进入和离开

- **进入**：`P` → 选中列表按 Enter → 在一条上按 Enter，进入这个列表的范围，从这一条开始。
  - 原来的做法是把这一条之后的条目倒进临时队列。现在不碰队列。
- **离开**：从曲库播放，就回到曲库范围。下面三种都算从曲库播放：
  - 在曲库里按 Enter；
  - 在曲库里双击；
  - 曲库范围里，停止时按空格（播放选中的那首）。
- **停止时按空格**：列表范围里，从当前条目开始放。列表播完停下时，当前条目就是最后一条，
  和曲库播完停下时按空格重播最后一首一样。
- **播完停下后**：仍然是这个列表的范围。
- **队列**：插播的整首放完，回到原来的范围接着走。在列表范围里，就接当前条目的下一条。

#### 顺序、循环和随机

- 列表范围用自己的 `PlaybackOrder`：范围是条目号 `0..条目数`，当前位置是当前条目的条目号。
  它和曲库的随机袋互不影响。
- **循环方式**：用这个列表的 `repeat`。
  - 列表范围里按 `z`，切换的是这个列表的循环方式，改了立刻写盘，提示“列表“睡前”循环：顺序”。
  - 配置文件里曲库的循环方式不变。
- **播完时的提示**：
  - 顺序播完最后一条：停止，提示“播放列表“睡前”已播完”。
  - “播完停止”：每条放完都停，提示和曲库一样。
- **随机**：开关和曲库共用一个，`s` 在两种范围里切的是同一个开关。在列表范围里打开时，在列表里洗牌。
- **系统媒体控制**：报告当前范围的循环方式；从系统那边改循环，改的也是当前范围的。
  - 系统只有“不循环”，没有“播完停止”和“顺序”之分。从系统关掉循环时：
    已经是这两种之一，就保持不变；从循环切过来，曲库改为“播完停止”，列表改为“顺序”（各自的默认）。
  - 能否上一首、下一首按当前范围算。

#### 上一首（`p`）

- 历史里每一项记下两件事：
  - 放的是什么：曲库的整首，或者哪个列表的哪一条和它当时的范围；
  - 当时的播放范围：列表范围还要记下当时的当前条目。
- `p` 退回时把两者一起恢复：
  - 是列表的条目，列表和条目都还在：回到那个列表的范围，当前条目落在它上面，按它现在的范围播放。
  - 是列表的条目，但列表或条目已经删掉：按历史里记下的范围放一次，当作插播，不改变播放范围。
  - 是曲库的整首：回到当时的范围，按曲库的规则播放。当时在列表范围里（那是一次插播），就回到那个列表、
    回到当时的当前条目；那个列表已经删掉时，回到曲库范围。

#### 播放中编辑这个列表

- **新增、移动条目**（加片段、`a` 加整首、`J` / `K`）：按编号找回当前条目；随机播放时重新洗牌，当前条目算已播。
- **删掉正在放的那一条**：这一条照样放完，然后接原来排在它后面的那一条。单曲循环时也接后面那一条；
  随机播放时，在剩下的条目里重新洗牌。
- **删除正在播放的列表**（播放列表面板的 `x`）：回到曲库范围，正在放的这一项照样放完，
  接着按曲库顺序放这个文件之后的那首。提示“已删除播放列表，播放回到曲库”。

#### 曲库那边

- 列表范围里，曲库中正在播放的那个文件照样有 ▶，光标也跟着它走，和现在的队列插播一样。
- 文件夹筛选只影响曲库范围。

### 6. 条目的播放

#### 装载

- **整首条目**：从 0:00 开始放到文件结尾。
- **片段**：用 `open_at` 直接从开头装载，开头之前的声音不会漏出来；再把结尾交给播放器作停止位置。
- **片段开头超出文件时长**（文件被剪短了）：跳过这一条，提示
  “已跳过“A · 掏耳”：片段开头 12:30 超出文件时长”。
  - 按扫描到的时长判断；装载失败时也同样跳过。
  - 不像曲库那样退回 0:00 播放。
- **结尾超出时长**：放到文件结尾为止，显示的长度也按文件结尾算。
- **文件不在曲库里**：跳过，提示“不在曲库中”，和现在一样。
- 装载时把条目的范围复制进播放项。之后在面板里改了这一条的范围，正在放的这一遍不受影响，下次播放才用新的。

#### 片段的结尾是硬的

- 片段放到结尾，这一条就放完了，接下一条。不记听完。
- **往后跳过结尾，直接放下一条**。这和曲库里跳过文件结尾一样，适用于下面几种跳转：
  - `→`、`L`；
  - `}`；
  - 鼠标点进度条最右端；
  - 系统媒体控制的相对跳转。
- 往前跳到开头为止，不会退到开头之前。
- 系统媒体控制用 SetPosition 跳到片段长度之外时，不动。这和现在跳到文件时长之外一样。
- **和录音终点的区别**：录音的终点是软的，跳过去就一直放到文件结尾；片段的结尾越过了，就是下一条。
  播放器不用改：App 不让跳转落在片段结尾或结尾之后，所以停止位置总是播放“一路走到”的。

#### 显示时间

- 下面这些都用显示时间，片段从 0:00 走到片段长度：
  - 进度条和时间；
  - `0–9`、鼠标点进度条、`←/→`、`H/L`；
  - 系统媒体控制的位置、长度、SetPosition 和 Seeked。
- `0`：回到条目开头（显示 0:00），不提示。录音的起点在列表里不起作用。
- 歌词照常按文件时间同步。
- 曲库列表里的时长列和收听进度条，照旧按整个文件显示。

#### 跳转点

- 面板、进度条上的 `|`、标题里的段名、`{` / `}`：只用片段开头（含）到结尾（不含）之间的跳转点，
  时间按显示时间写。
- `{` 在第一个跳转点之前按：回到片段开头，提示“跳到开头”。
- `}` 在最后一个跳转点之后按：提示“后面没有跳转点”。
- `b`：照常在当前位置加跳转点，按文件时间存，提示里写显示时间。
- 面板的 `s` / `S`：在列表范围里不可用，提示“播放列表里不用录音的起点和终点，从曲库播放时再设”。
- 面板的 `a`：照常可用，用来加片段，见第 10 节。

#### 睡眠定时“本条”

- 片段在片段结尾停，淡出按离片段结尾的时间算。
- 整首条目在文件结尾停，不用录音的终点。

#### 系统媒体控制的标题和曲目 ID

- **标题**：片段（或起了名的整首条目）显示为“文件名 · 名字”。隐私模式照旧只显示“正在播放”。
- **曲目 ID**：改为每装载一次换一个，即 `/org/mpris/MediaPlayer2/Track/<序号>`。
  - 这样同一个文件的两个片段先后播放时，桌面小组件才知道换了曲目，会刷新长度。
  - 曲库播放也照此处理，单曲循环每重播一遍也换一个 ID，没有坏处。

### 7. 收听进度、录音的起点和终点

列表范围里的条目，无论整首还是片段，都不碰收听进度和录音的起点终点：

- 不读收听进度：不续播。
- 不写收听进度：不记位置，也不记听完。
- 不用录音的起点：不自动跳过开头。
- 不用录音的终点：不在终点停。播放器的停止位置只按条目的结尾设。

队列里的插播是曲库播放，以上照常。`opening`、`note_progress`、`mark_finished`、`apply_stop`
都按播放项的来源分开处理。

### 8. 会话

```toml
version = 1
library_dir = "/home/tyzq/Music"
track = "/home/tyzq/Music/ASMR(Rica)/A.m4a"
position_ms = 812000
playlist = "睡前"
entry = 3
```

- 只有当前播放项是列表条目时，才写 `playlist` 和 `entry`。`entry` 是第几条，从 1 数起。
- 位置照旧存文件时间。报告里说存片段内的时间，这里改了：旧版本读到这个文件时会忽略那两个字段，
  恢复到同一个文件的同一个位置。存片段内的时间的话，旧版本会恢复到错的位置。
- **恢复**：列表还在、第几条还在、路径也对得上时，进入列表范围，当前条目落在这一条上，
  从记下的位置装载并暂停。
  - 位置在这一条的范围之外（条目被改过），或者离结尾 3 秒以内：从这一条的开头装载。
  - 列表或条目对不上：当作曲库播放来恢复，和现在一样。
- 恢复的提示用显示时间，例如：“已恢复上次播放：睡前 3/12 A · 掏耳 2:10，按空格继续”。

### 9. 改名跟随

扫描完成后，和收听进度、跳转点一起处理：

1. 曲库里有这个路径的条目：补上或更新 `file_size` 和 `modified_ns`。从 v1 转来的条目第一次补上；
   文件改过标签时更新。
2. 曲库里找不到的路径（只看音乐库目录下的）：
   - 大小和修改时间相同的失联路径只有一个，曲库里大小和修改时间相同的文件也只有一个时，
     所有列表里指向这个路径的条目都改到新路径。
   - 两边任何一边有多个时都不动。这是 BUG-008 修复后的规则。
   - 和收听进度不同，不要求新文件“自己还没有记录”，因为列表里本来就可以有同一个文件。
3. 有改动的列表写盘。

另外：

- 找不到的条目保留，面板里标“不在曲库中”，播放时跳过。
- 还没有 `file_size` 的条目（从 v1 转来，还没扫描到过）不跟随。

### 10. 编辑

#### 加片段（跳转点面板的 `a`）

- 选中一个跳转点按 `a`：
  - 片段从它开始，到下一个跳转点为止；它是最后一个时，到文件结尾。
  - 下一个跳转点按整个文件算：正在放片段时，面板里只列出片段以内的跳转点，但片段可以延伸到片段之外。
  - 片段名用这个跳转点的名字；跳转点没有名字时，片段也没有名字。
- 接着弹出“加到播放列表”面板：
  - 列出所有播放列表和各自的条目数，光标落在这次运行里上一次加过的列表上。
  - `Enter` 加到选中的列表；`c` 新建一个列表再加；`Esc` 回到跳转点面板。
- 加好后回到跳转点面板，提示“已加进“睡前”：掏耳（17:50）”；片段没有名字时提示“已加进“睡前”：17:50 的片段”。
  - 提示写片段长度，不写起止：正在放片段时，面板显示的是片段内的时间，写起止容易混淆。
- 起止时间在这时复制进列表，之后改动或删除跳转点，都不影响已经加好的片段。
- 只能给正在播放的录音加片段：跳转点面板只对正在播放的录音打开。
- 加到正在播放的列表：新条目排在末尾，当前条目不变；随机播放时重新洗牌。

#### 加整首（播放列表面板的 `a`）

- 照旧：把曲库里选中的那首加到选中列表的末尾。
- 列表里已经有这首的整首条目时照样加，提示“已加入“睡前”（列表里已有这首，现在有 2 条）”。

#### 列表条目面板

- **标题**：“ 睡前 · 12 条 · 顺序 ”。
- **每行**：
  - 序号和文件名；
  - 片段或起了名的条目，接“ · 名字”；
  - 片段接文件里的起止，例如“12:30–30:20”；整首接文件时长。
  - 这个列表是当前播放范围时，当前条目用 ● 标出。
  - 文件不在曲库中：⚠ 加红色，标“不在曲库中”。改为按曲库解析，不再每画一帧都对每一行调用 `is_file()`。
- **按键**：

| 按键 | 操作 |
|---|---|
| `Enter` | 从这一条开始播放（进入列表范围） |
| `J` / `K` | 下移 / 上移 |
| `s` / `S` | 改开头 / 结尾 |
| `e` | 改名（留空清除名字） |
| `d` | 从列表移除，不再确认（和队列一样） |
| `Esc` | 返回播放列表面板 |

- **改开头、结尾**（`s` / `S`）：弹出这个文件的跳转点让你挑。
  - 改开头时列出：0:00（文件开头），以及结尾之前的跳转点。
  - 改结尾时列出：开头之后的跳转点，以及“文件结尾”。
  - 跳转点按文件时间显示，带名字，以及“起点”“终点”标签。光标落在现在的开头或结尾上；
    `Enter` 选定，`Esc` 取消。
  - 选定后提示，例如“开头改为 12:30 掏耳”。
  - 整首条目改了开头或结尾，就成了片段；开头改回 0:00、结尾改回文件结尾，又成了整首。
  - 文件不在曲库中，或者没有可选的跳转点（短曲目、还没设跳转点）：只提示“这首没有跳转点，只能整首播放”。
  - 跳转点按路径从 `MarkStore` 取，文件不在播放也能改。
- **改名**：弹出输入框，预填现有的名字；留空就清除名字。

#### 播放列表面板

- 每行写名字、条目数和循环方式，例如“睡前  12 条 · 顺序”。当前播放范围所在的列表用 ● 标出。
- 按键不变：`c` 新建、`a` 加入选中歌曲、`Enter` 查看、`x` 删除、`Esc` 关闭。

### 11. 显示

   - 这一步条目的开头总是 0:00，结果和现在完全一样。现有测试一行不改，全部通过。
2. **播放列表 v2**（`src/playlist.rs`）：

     - 曲库里 Enter 离开列表范围；插播放完回到列表接下一条。
     - `p` 回到列表范围；条目删了只当插播。
     - 删掉正在放的那一条、移动条目、删除正在播放的列表。

### 13. 验收

用户在自己的 kitty 中，用隔离的 XDG 目录打开 `~/Music`。改名验证用复制到临时目录的文件，不改动 `~/Music`：

- **建列表**：播放一个有几个跳转点的长录音，`B` 选一个跳转点按 `a`，新建列表“测试”加进去；
  再加另一个录音的两段和一首整首歌。
- **看条目**：`P` → 测试 → Enter。片段显示名字和起止，整首显示时长。
- **从第一条开始**：在第一条上 Enter。
  - 从片段开头开始，开头之前没有漏出声音。
  - 时间从 0:00 走，进度条的长度是片段长度，状态栏显示“测试 1/4 · 顺序”。
- **片段的结尾**：放到结尾自动接下一条；`L` 越过结尾直接下一条；`H` 退不过开头。
- **循环**：放完最后一条停止，并提示列表已播完。`z` 切成列表循环后再放，会转回第一条；
  `config.kdl` 里的循环方式不变。
- **随机**：打开随机时，列表里每条放一次。
- **离开和回来**：曲库里 Enter 一首歌，回到曲库范围；`p` 回到列表的那一条，状态栏又是列表。
- **编辑**：在条目面板里 `J/K` 移动、`s/S` 改开头和结尾、`e` 改名、`d` 删除。
  删掉正在放的那一条后，它放完接原来在它后面的那条。
- **系统媒体控制**：放片段时，`playerctl -p nemuri metadata` 显示“文件名 · 片段名”和片段长度，
  `playerctl -p nemuri position` 是片段内的时间。
- **不碰收听进度**：一个设了起点、有收听进度的录音在列表里从片段开头放；退出后曲库里它的收听进度没有变。
- **会话**：退出重开，回到列表的那一条和原来的位置。
- **v1 列表**：把一个 v1 列表复制进播放列表目录，能读能播；改动之后文件变成 v2。
- **读不了的列表**：
  - 把一个列表文件写坏后启动：提示已改名保留。
  - 写一个 `"version": 3` 的列表：提示版本不受支持；新建同名列表被拒绝，原文件没有被覆盖。
- **改名跟随**：在临时音乐库里把列表里的文件改名，按 `r` 重扫，条目跟到新文件名上。

### 14. 这一版不做

- 片段之间无缝衔接：每一条都重新装载，切换时有短暂的空隙，和现在切歌一样。
- 把片段排进队列，以及在队列面板里显示片段。
- 手动输入片段的起止时间：只能从跳转点里挑。
- 给不在播放的录音加片段：跳转点面板只对正在播放的录音打开。不过已经在列表里的片段，不在播放也能改起止。
- 播放列表本身的改名、复制、导入和导出。
- BUG-009（非 UTF-8 文件名命中扫描缓存）。

### 16. 实现记录

七个提交依次对应第 12 节第 1–7 步。和上面的计划不同或计划没写到的地方：

- **状态栏提前到第 3 步**：第 11 节的“睡前 3/12”在第 3 步就加上了，不然进了列表范围在界面上看不出来。
  列表名在状态栏里最多占 12 列。
- **帮助改在 `P` 一行**：第 11 节说改 `z` 一行，但加上说明后超出帮助弹层的宽度。改为 `P` 一行写
  “播放列表（每个列表各记循环方式，z 切换）”，`z` 一行不变。
- **面板宽度和提示**：跳转点面板加上 `a 加入列表` 后从 64 列加宽到 76 列。条目面板仍是 78 列，
  `d` 的提示从“从列表移除”改为“移除”，才放得下一行。
- **纯文本歌词按整个文件的进度滚动**（第 1 步）：歌词对应整个文件，放片段时也不按片段内的进度滚。
- **列表放完的提示**：不只自然播完最后一条，在最后一条上按 `n` 也提示“播放列表“睡前”已播完”。
- **跳到片段结尾上也算越过**：播放器的停止位置只在一路播到时才生效，跳到它上面会一直放到文件结尾，
  所以 App 把跳到正好片段结尾也当作下一条。曲库播放跳到正好文件结尾时，照旧让它自己播完。
- **跳转点面板换了一段就重新落位**：面板记的是“哪一项”（文件和来源），同一个文件的另一段也算换了一项，
  光标回到当前所在段。原来只按文件路径比。
- **会话恢复片段时的退路**：从记下的位置装载失败时，片段退回片段开头，不退回 0:00；曲库播放照旧退回 0:00。
  片段开头已经在文件之外时，按曲库播放恢复。
- **改名跟随多两种不跟的情况**（第 5 步）：同一个路径的几条条目记的大小和修改时间不一样时，说不清是哪个文件，
  不跟；新路径不是 UTF-8 时也不跟，否则这个列表以后都写不了盘。
- **删除文件已经不在的列表**：原来报错，现在直接从面板里去掉。
- **读不了的列表的提示**改为“播放列表文件无法识别，已改名保留为 …”，和收听进度、跳转点的说法一致；
  启动提示的测试跟着改了要找的词。
- **条目改名**：成功时不提示，和跳转点改名一样；写盘失败时才说明。
- **BUG-010 的修法**：没有采用“写成了才改内存”，而是和跳转点一样留在内存里、之后改动和退出时再写，
  见 `known_issues.md`。
