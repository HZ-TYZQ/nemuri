# Plan for version 2.1.0

## feature:

- 长录音跳转点：每个长录音可以记下多个位置，按键或面板直接跳过去（见下）
- 起点和终点：把跳转点设为起点、终点，播放时自动跳过开头和结尾（见“起点和终点”一节）

## 长录音跳转点

状态：已实现（分支 `feat/jump-marks`），等待用户验收；实现时的调整见第 9 节
范围：只做“一个作品多个跳转点”；固定起点（播放时自动跳过开头）以后单独做，见第 8 节

### 1. 目标

ASMR 长录音常常分成几段（掏耳、耳语、哄睡……），想听某一段时只能用 `←/→`、`H/L`
或 `0–9` 一点点找。跳转点让用户在听的时候按一下记下位置，之后直接跳回去。

### 2. 用户决定（2026-10-16）

- 做多个跳转点（书签）；固定起点以后再加。
- 只限长录音：和收听进度用同一个判断 `progress::is_long`（扫描时长 ≥ 10 分钟）。
- 按键：`b` 在当前位置加跳转点，`B` 打开跳转点面板，`{` / `}` 跳到上一个 / 下一个。

### 3. 数据

单独存 `$XDG_DATA_HOME/nemuri/marks.json`（Windows 为 `%APPDATA%\nemuri\marks.json`），
不并进 `progress.json`：

- 收听进度拖回开头时整条记录会删掉（`ProgressStore::set` 收到 `None`），跳转点不能跟着没了；
- 收听进度最多 30 秒写一次盘，跳转点是少见的手动操作，改了就写；
- 两份文件互不牵连，一份坏了不影响另一份。

格式：

```json
{
  "version": 1,
  "recordings": [
    {
      "path": "/home/tyzq/Music/ASMR(Rica)/音频 - ….m4a",
      "file_size": 123456789,
      "modified_ns": 1760000000000000000,
      "marks": [
        { "position_ms": 750000, "name": "掏耳" },
        { "position_ms": 1820500 }
      ]
    }
  ]
}
```

- 跳转点按位置排序，精确到毫秒；`name` 可省略，没有名字时界面显示时间（`fmt_duration`）。
- 一个录音的跳转点删光时，整条记录删掉。
- 按 `recordings` 而不是平铺的跳转点列表来存，以后的固定起点可以作为同一条记录里的字段加进来。
- 文件改名后的处理和收听进度相同：重扫时靠 `file_size` + `modified_ns` 找回，
  只在恰好有一个候选、且候选自己没有记录时才搬；找不到的记录保留（比如移动硬盘没挂上）。
- 读不了或版本不对时改名保留为 `marks.json.corrupt-<纳秒>`，从空记录开始，底栏提示。
- JSON 只能存 UTF-8 路径。收听进度遇到非 UTF-8 路径是静默不记；跳转点是用户主动加的，
  不能静默丢，所以这种文件按 `b` 时直接提示不支持。
- 时长变短（文件被剪过）后超出时长的跳转点保留，但不显示、不参与跳转。

### 4. 交互

#### 曲库界面

| 按键 | 操作 |
|---|---|
| `b` | 在当前位置加跳转点，不问名字；底栏提示“已添加跳转点 12:30（B 管理）” |
| `B` | 打开当前曲目的跳转点面板 |
| `{` | 跳到上一个跳转点 |
| `}` | 跳到下一个跳转点 |

- 只对正在播放（或暂停中）的曲目生效，不是选中的曲目。
- 当前曲目不是长录音时，四个键都只提示“只有 10 分钟以上的录音能设跳转点”。
- 播放器停止（还没播放，或“播完停止”后）时没有位置可记、可跳，只给提示，不改变播放状态。
  这和现在 `SeekTo` 在停止状态下不生效一致。
- 离已有跳转点不到 1 秒时不重复添加，提示“这里已有跳转点 12:30”。
- `{`：跳到不晚于“当前位置减 3 秒”的最后一个跳转点；没有就回到 0:00。
  所以刚跳到某个点之后 3 秒内再按，会跳到再前面一个。
- `}`：跳到晚于“当前位置加 1 秒”的第一个跳转点；没有就提示“后面没有跳转点”，
  不跳到结尾（免得记成听完）。1 秒的余量是因为跳转后实际位置可能比跳转点早一点。
- 跳转一律走 `seek_to_requested`，MPRIS / SMTC 照常收到 Seeked，收听进度照常记录。
- 当前录音没有跳转点时，`B`、`{`、`}` 都只提示“这首还没有跳转点，按 b 在当前位置添加”：
  `B` 不打开空面板，`{` 也不回到 0:00。`{` 挨着音量键，没有跳转点时误按一下就跳回开头，
  收听进度也跟着没了。

#### 跳转点面板（新的 `Overlay::Marks`）

- 标题：`跳转点 · <曲名>`。每行是时间加名字，没有名字时只显示时间。
- 打开时光标落在当前所在的那一段（不晚于当前位置的最后一个跳转点），这一行用 ● 标出
  （和文件夹面板标出当前筛选一样）。
- `Enter` 跳过去并关闭面板（和文件夹面板一样）；`d` 删除，不再确认（和队列的 `d` 一样）；
  `e` 改名；`Esc` 或 `B` 关闭。鼠标单击选中、双击跳转，和其他面板一致。
- 删到一个不剩时关闭面板并提示。
- 面板开着时换了曲目（自然播完接下一首、系统媒体控制切歌），面板跟着换成新曲目的跳转点；
  新曲目不是长录音或没有跳转点时关闭面板。

#### 改名

- 新增 `Overlay::MarkName`，沿用 `draw_text_popup` 和 `view.name_input`，打开时预填现有名字。
  现有的 `NameInput` 确认时会新建播放列表、返回时回到播放列表面板，不能直接拿来用。
- `Enter` 确认：去掉首尾空白后为空就清除名字，恢复只显示时间；`Esc` 回到跳转点面板。

### 5. 显示

- 进度条：`ascii_progress_bar` 多传一组跳转点的比例，在对应的格子上画 `|`；
  和播放头 `>` 落在同一格时显示播放头。
- 正在播放区：当前所在段有名字时，边框标题显示 `♫ 正在播放 · 掏耳`，宽度不够时截断名字。
  放在标题里，不和右边的状态栏抢宽度；第一个跳转点之前、或当前段没有名字时不显示。
- 帮助弹层由按键表生成，新增两行：`b / B`（加跳转点 / 跳转点面板）、`{ / }`（上一个 / 下一个跳转点）。
  底栏不加简写，底栏已经很挤。
- 段名只在终端界面显示，不送到 MPRIS / SMTC，隐私模式不用另外处理。

### 7. 验收

用户在自己的 kitty 中用隔离的 XDG 目录打开 `~/Music`；改名验证使用复制到临时目录的文件，
不改动 `~/Music`：

- 播放一个长录音，按三次 `b`（不同位置），进度条上出现三个 `|`，`B` 面板按时间列出；
- `e` 改名后标题栏显示段名；清空名字后面板只显示时间，标题栏不显示段名；
- `}` 依次往后跳，最后一个之后提示；跳到某点后 3 秒内按 `{` 跳到再前一个，第一个之前按 `{` 回到 0:00；
- 暂停中能加、能跳，跳完仍是暂停；停止状态只提示；
- 在 `Music` 文件夹的普通歌曲上按 `b` / `B` / `{` / `}` 只提示，不生成 `marks.json`；
- 还没有跳转点的长录音上按 `{` 只提示，不回到开头；
- 退出重开后跳转点都在，`marks.json` 内容和面板一致；
- 在临时目录里给文件改名，按 `r` 重扫后跳转点跟到新文件名上；
- 把 `marks.json` 写坏后启动，提示已改名保留，跳转点从空开始，收听进度不受影响；
- 跳转后 `playerctl -p nemuri position` 显示新位置。

## 起点和终点

状态：计划已定（分支 `feat/start-point`），尚未开工
来源：上面“长录音跳转点”第 8 节留下的固定起点；终点和以后的片段播放列表见
`clip_playlists_feasibility.md`，这一节是那份报告第 5 节的第 1 步

### 1. 目标

很多 ASMR 录音开头和结尾各有一段不想每次都听的内容（开场白、注意事项、广告、片尾的感谢和预告）。
给录音设起点和终点后，本来要从 0:00 开始时直接从起点开始，播到终点就算这一首播完，接着放下一首。

### 2. 用户决定（2026-10-16）

1. **起点和终点都是跳转点**：在跳转点面板里选中一个，按 `s` 设为起点、按 `S` 设为终点，再按一次取消。
   每个录音最多一个起点、一个终点，设新的时旧的变回普通跳转点；起点要在终点之前。
   - 起点和终点因此和其他跳转点一样能改名、删除、用 `{` / `}` 跳到，进度条上也有 `|`；
     改名跟随、文件剪短后不显示等规则全部沿用，不用另做一套界面。
   - 设的步骤：听到正文开始（或片尾开始）时按 `b`，再按 `B`（光标正好落在刚加的点上），再按 `s`（或 `S`）。
   - 不做独立的起止点：那要多一套按键和显示，而且一个录音可以只有起止点没有跳转点，
     “跳转点删光即删记录”的规则也要改。
2. **`0` 先回到起点**：有起点时，`0` 跳到起点；已经在起点或起点之前（不晚于起点后 3 秒）时跳到 0:00。
   规则和 `{` 一样，连按两次 `0` 总是回到 0:00。
   - 续播提示随之改为“从 12:34 继续（按 0 回到起点）”。从中间“从头再听一遍”时也跳过开头。
   - 只改 `0` 键。鼠标点进度条最左边、系统媒体控制跳到 0 仍然是 0:00。
3. **只在面板里设**，曲库界面不加按键。以后觉得 `b` `B` `s` 三步太慢，可以再加一个键在当前位置直接设起点。
4. **终点是软的**：只在正常播放越过终点时停；用户自己跳到终点或终点之后（`→`、`L`、`0–9`、`}`、鼠标、
   系统媒体控制），就一直放到文件结尾，片尾还能听到。和“起点之前的开头还能听”对称。
5. **时间显示仍是整个文件**：进度条、时间、系统媒体控制都和现在一样，起点之前和终点之后的部分照常显示。
6. **只在曲库播放时生效**：从曲库、队列和（这一版的）播放列表播放都是曲库播放，起点和终点照常生效。
   2.2.0 的片段播放列表里，条目只按自己的范围播放，不用录音的起点和终点
   （见 `clip_playlists_feasibility.md` 第 1 节第 7 项）。

### 3. 起点：什么时候自动跳过去

只在装载一首长录音、本来要从 0:00 开始时跳，和续播是同一个地方（`play_index` 里的 `resume_point`）：

- 没听过的录音；
- 上次已经听完，这次重听，包括单曲循环自然播完后重播、列表循环转回来；
- 收听进度因为拖回开头而删掉的录音；
- 记下的进度不晚于起点后 3 秒，或者已经在终点前 3 秒以内（设起点、终点之前记下的，见第 5 节）；
- 启动时恢复会话，上次停在终点前 3 秒以内或终点之后（没有终点时是结尾 3 秒以内）：
  现在退回 0:00，改为退回起点。

不跳的情况：

- 有收听进度时照常续播。
- 播放中用 `←` / `H` / `{` / 鼠标 / 系统媒体控制退到起点之前：用户自己要听开头，不再跳回去。
- 启动时恢复会话，上次停的位置不在终点附近：照原位置恢复，即使在起点之前。

装载时直接从起点打开（和续播一样用 `open_at`），不是先从 0:00 播放再跳，开头一点声音也不会漏出来。
系统媒体控制拿到的位置就是起点。

### 4. 终点：在哪里停

播放器多一个“停止位置”：播到这里就当作这一首播完了，和自然播完走同一条路
（`PlayerEvent::EndOfStream` → 记为听完 → 按循环方式接下一首，或者“播完停止”时停下并提示）。

- 停止位置由 App 设给播放器，只在三种时候设或清：
  - **装载之后**（换曲、续播、从起点开始、单曲循环重播、恢复会话）：开始位置在终点之前就设为终点，否则不设；
  - **每次跳转之后**（`←/→`、`H/L`、`0–9`、`0`、`{` / `}`、面板跳转、鼠标、系统媒体控制）：
    跳到终点之前就设为终点，跳到终点或终点之后就清掉，一直放到文件结尾；
  - **终点改动之后**（设、取消、删除，以及重扫后改名跟随带来的终点）：当前位置在新终点之前就设，否则清掉。
- 不在每个 tick 按当前位置判断：播到终点的那一刻位置可能刚好越过一点，按位置判断会把停止位置清掉，
  播过头。
- 单曲循环：播到终点后重播，从起点开始，所以循环的是起点到终点这一段。
- 睡眠定时“本条”：在终点停；淡出按离终点的剩余时间算（`src/app/sleep.rs`）。停止位置已经清掉时
  （用户跳过了终点），按离文件结尾的时间算。
- 终点超出时长（文件被剪短）：和超出时长的跳转点一样不显示，也不生效。
- 短于 10 分钟的曲目没有跳转点，也就没有起点和终点。

### 5. 收听进度

`ProgressStore` 不认识跳转点：起点和终点由 App 层查好，作为参数传给 `record`。没有起点时起点是 0:00，
没有终点时终点是文件时长，规则就和现在一样。

- **没开始听**：“离开头 3 秒内”改为“不晚于起点后 3 秒”。不改的话，打开一首已经听完的录音、
  自动跳到起点后马上会被记成“听到 1:30”，“✓ 听完”就没了；刚打开就关掉的录音在曲库里也会显示成听过几个百分点。
  退回起点之前听开头时也不记进度，下次从起点开始。
- **听完**：“离结尾 3 秒内”改为“离终点 3 秒内或在终点之后”。用户跳过终点去听片尾时，这一首记为听完，
  下次从起点开始。
- 曲库里的百分比照旧按整个文件算，不扣掉开头和结尾，和进度条、时长显示一致。

### 6. 交互和显示

| 操作 | 结果和提示 |
|---|---|
| 自动从起点开始 | “已跳过开头，从起点 1:30 开始” |
| 续播（有起点） | “从 12:34 继续（按 0 回到起点）”；没有起点时提示不变 |
| `0`，在起点后 3 秒以外 | 跳到起点，“回到起点 1:30（再按 0 从 0:00 播放）” |
| `0`，在起点后 3 秒以内或起点之前 | 跳到 0:00，“跳到开头” |
| `0`，没有起点或不是长录音 | 和现在一样跳到 0:00，不提示 |
| 播到终点 | 和播完一样，接下一首；“播完停止”时提示“已播完，播放停止（按 z 切换循环方式）” |
| 跳到终点或终点之后 | 一直放到文件结尾，不提示 |
| 面板 `s`，选中普通跳转点 | 设为起点，“已设为起点 1:30，以后从头播放时从这里开始” |
| 面板 `s`，选中的已经是起点 | 取消，“已取消起点，以后从 0:00 开始” |
| 面板 `S`，选中普通跳转点 | 设为终点，“已设为终点 58:20，以后播到这里就算播完” |
| 面板 `S`，选中的已经是终点 | 取消，“已取消终点，以后播到文件结尾” |
| 面板 `s`，选中的点不在终点之前 | 不改，“起点要在终点 58:20 之前” |
| 面板 `S`，选中的点不在起点之后 | 不改，“终点要在起点 1:30 之后” |
| 面板 `d` 删掉起点 | “已删除起点 1:30，以后从 0:00 开始” |
| 面板 `d` 删掉终点 | “已删除终点 58:20，以后播到文件结尾” |

- 起点和终点只在面板里设。设或取消后立刻写盘，和其他跳转点的改动一样；跳转点文件只读时
  （启动时没能读取或保留）提示不能改动，和 `b` 一样。
- 提示里提到起点、终点时写作“起点 1:30”“终点 58:20”，有名字时接在后面，例如 `{` / `}` / 面板跳过去时
  “跳到起点 1:30 正片”。
- 面板：起点、终点那一行在名字后面用暗色标“起点”“终点”；面板底部提示加一条 `s / S 起点 / 终点`，
  实现时确认 60 列宽的面板放得下。
- 进度条：起点和终点和其他跳转点一样画 `|`，不另加符号。ASCII 进度条没有合适的字符，
  哪个是起点、终点在面板里看得出来。
- 帮助：`0–9` 那一行改为“跳到 0% – 90% 位置（有起点时 0 先回到起点）”。
- 暂停中按 `0` 照常跳转、仍是暂停；停止状态不动，和现在一样。

### 7. 数据

起点和终点记在 `marks.json` 里对应的跳转点上：

```json
"marks": [
  { "position_ms": 90000, "name": "正片", "start": true },
  { "position_ms": 750000, "name": "掏耳" },
  { "position_ms": 3500000, "end": true }
]
```

- 不是起点、终点时不写 `start`、`end`。
- 读文件时（文件可能被手改过）：多个起点只认最早的，多个终点只认最晚的；一个跳转点同时标了两个时只算起点；
  终点不在起点之后时去掉终点。去掉的只是标志，跳转点本身保留。
- 标在跳转点上，而不是在 `recordings` 里另存 `start_ms`、`end_ms`：不会出现指向不存在的跳转点的起止点，
  删掉那个跳转点，起点或终点也就没了。
- 内存里每个跳转点带一个角色（普通 / 起点 / 终点），不用两个布尔值，免得出现同时是起点和终点的状态。
- 不升 `version`：`marks.json` 还没有随正式版发布过（2.1.0 未发布），没有 `start`、`end` 的文件照常读。
  这个分支之前的开发构建读到新文件时会忽略这两个字段，保存时丢掉它们；只影响开发期间来回切换版本，不处理。

### 9. 验收

用户在自己的 kitty 中用隔离的 XDG 目录打开 `~/Music`：

- 长录音上按 `b` `B` `s` 设起点、`b` `B` `S` 设终点，面板里那两行标“起点”“终点”；退出重开仍在，
  `marks.json` 里对应的两条有 `"start": true` 和 `"end": true`；
- 曲库里 Enter 一首设了起点、没听过的录音：直接从起点开始，开头没有漏出声音，底栏说明；
- 自动跳过后 3 秒内按 `0` 回到 0:00；听一会儿按 `0` 回到起点，再按一次回到 0:00；
- 续播这首时提示“按 0 回到起点”；
- 播到终点：接下一首；“播完停止”时停下并提示；曲库里这首显示“✓ 听完”；
- 终点前按 `L` 跳过终点：一直放到文件结尾；再退回终点之前，又会在终点停；
- 单曲循环下从起点放到终点，再从起点重播；
- 睡眠定时选“本条”：在终点停，淡出在终点之前完成；
- 打开一首已听完、设了起点的录音，马上退出：曲库里仍显示“✓ 听完”；
- 起点上再按 `s` 取消，之后从 0:00 开始；终点上再按 `S` 取消，之后播到文件结尾；
  另选一个设为起点，旧的变回普通跳转点；在终点之后的点上按 `s` 只提示不改；
- 没有起点的录音和短曲目上，`0` 照旧回到 0:00；
- 自动跳过后 `playerctl -p nemuri position` 显示起点的位置；播到终点后 `playerctl` 显示已换到下一首。
