# ASMR 优先播放器转向计划

状态：里程碑 1–3 已完成并推送；里程碑 4（改名为 Nemuri）已实施，2.0.0 稍后单独发布
范围：从 1.4.0 的终端音乐播放器出发，转向以 ASMR 为主、普通音乐照常可用的播放器

## 1. 目标

普通音乐播放器同质化严重。ASMR 的使用方式和听歌不同：单个录音很长，常常听着睡着，
内容按创作者整理，文件名比标签可靠。播放器按这些特点调整，而不是重写：
1.4.0 已经把播放后端、App 状态和输入动作分开，转向主要改曲库模型、播放顺序和界面。

## 2. 用户决定

- ASMR 优先，但 `Music/` 这类普通音乐照常播放：队列、随机、歌词都保留。
- Opus 继续暂不支持，等 Rodio 正式版带上 libopus 接口再接（见第 5 节）。
- 名称照磁盘上的原样显示：标题就是文件名（不含扩展名），不剥前缀、不解析命名规律，
  这样别人用别的命名方式也能用。文件改名后在下次扫描（启动或按 `r`）时更新，不监视文件系统。
- 分组按音乐库根目录下的第一层文件夹，名称原样显示；直接放在根目录的文件归入“(根目录)”。
- 录音自然播完后默认停止；循环、随机和队列在打开时照常工作。

## 3. 测试曲库的实际情况

`~/Music` 是用户自己的曲库，只读使用：

| 文件夹 | 文件数 | 说明 |
|---|---|---|
| `ASMR(Macoto)` | 3 | FLAC 24/48 与 M4A，1 小时到 2 小时 |
| `ASMR(Other)_author)` | 3 | 杂项创作者，含一个 MP3 |
| `ASMR(Rica)` | 1 | M4A，内嵌 Whisper 生成的同步 LRC |
| `ASMR(月紫)` | 1 | M4A，3 小时 15 分 |
| `ASMR(衣鶴)` | 3 | FLAC 合集，约 25–30 分钟 |
| `Music` | 1 | 普通歌曲 |
| `ASMR` | 0 | 空文件夹 |

- 全部是从 B 站下载的单个长录音（14 分钟到 3 小时 15 分），不是多音轨的 DLsite 作品；文件名都以 `音频 - ` 开头。
- 标签标题不可靠：`涩涩ASMR.mp3` 的标签标题是 `studio_video_1761120035627.mp4`；
  `（8分34秒起·已裁剪静音）` 这类备注只写在文件名里。
- 歌手标签有的有、有的没有，写法也可能和文件夹不同（文件夹 `衣鶴`，标签 `衣鹤`）。
- 多个 M4A 内嵌 Whisper 识别的同步 LRC，现有歌词面板已经能当字幕显示；
  `衣鶴` 的 FLAC 内嵌歌词是一行占位文字“纯音乐”。

## 4. 里程碑

### 里程碑 1：原名显示、文件夹筛选、播完停止

1. 曲库、正在播放、队列和系统媒体控制都显示文件名；标签标题、歌手、专辑仍可搜索。
2. 曲库第二行改为“文件夹 · 歌手 · 专辑 · 格式”，没有的项省略。
3. `f` 打开文件夹面板，列出“全部”和每个文件夹的曲目数，选中后只看该文件夹；
   搜索在筛选范围内进行。筛选只在本次运行有效（里程碑 2 起随会话保存）。
4. 顺序播放、列表循环和随机只在当前文件夹内进行；搜索只用来定位，不改变播放范围。
5. 新增循环方式“播完停止”，并成为新配置的默认值：`z` 依次切换 播完停止 / 顺序 / 列表循环 / 单曲循环。
   已有配置文件保留原来的值。

### 里程碑 2：睡眠与续听

- 睡眠定时（预留 `t`）：N 分钟后、本条播完时；停止前用 30–60 秒淡出。
  淡出用后端里独立的增益系数，不改用户音量，避免被写回配置或显示在界面上。
- 每个录音各自记住播放位置，曲库中显示已听进度；进度属于用户数据，不放在可删除的缓存里。
- 记住文件夹筛选。

### 里程碑 3：隐私与声道

- 隐私模式：向 MPRIS/SMTC 只发送通用标题，并且不发送文件路径（MPRIS 的 `url` 会暴露文件夹和标题）。
  `i` 开关，默认关闭，随配置保存；标题为“正在播放”，时长、进度和控制照常；正在播放区域显示“隐私”。
- 左右平衡、左右声道互换（耳机戴反时用）。`,` / `.` 每次挪 10，`w` 互换，两项都随配置保存，
  不是默认值时显示在正在播放区域。平衡在互换之后生效，指的是耳朵这一侧；单声道先复制成两个声道。
- 处理“纯音乐”这类占位歌词：每一行都是占位文字时当作没有歌词，`.lrc` 是占位文字时改用内嵌歌词。
- 顺带修复：帮助弹层在 24 行的终端里放不下，改为可以滚动。

### 里程碑 4：改名与 2.0

产品形态稳定后再统一改名：包名、二进制、spec、desktop、man、Windows 安装包、CI 和配置目录迁移一次完成。

2026-10-14 的决定：
- 新名字 `nemuri`（眠り，睡眠）：命令、软件包和目录都叫 `nemuri`，显示名 Nemuri。
- 旧数据：第一次启动时新目录不存在，就把 `tui-music-player` 的配置和数据目录复制过去，旧目录原样保留；缓存不复制。复制失败时不启动。
- RPM 用 `Provides`/`Obsoletes: music-player` 替换旧包；Windows 安装程序沿用 AppId 原地升级，删掉旧名字的文件和开始菜单项，PATH 标记的注册表键沿用旧名。
- GitHub 仓库改名为 `HZ-TYZQ/nemuri`，推送时进行。
- 先只改名，版本仍是 1.4.0；2.0.0 用之后的 release-prep 提交发布。

## 5. Opus 现状（2026-10-13 核实）

- Rodio master 已合并 PR #851（2026-03-11）：新增 `symphonia-libopus` feature
  （依赖 `symphonia-adapter-libopus` 0.2，基于 symphonia-core 0.5）
  和 `DecoderBuilder::with_symphonia_decoder`，可注册第三方解码器。
- 这些改动不在任何已发布版本中：0.22.2 的 crate 源码里没有，master 的 CHANGELOG 把它记在 0.22.2 下是记错了位置；
  0.23.0（2026-10-11）是只升级 cpal 0.18.2 的最小版本，同样没有。
- 下一个大版本和音频引擎重写（#901）、升级 Symphonia 0.6（#919）绑在一起，时间未定。
- 决定：等 Rodio 正式版。届时用 `.with_symphonia_decoder::<OpusDecoder>()` 接入，
  并处理 libopus 的 C 依赖（`opusic-sys` 默认用 cmake 编译）、RPM 与 Windows 构建以及 BSD-3-Clause 声明。
  升级 0.23.0 本身对 Opus 没有帮助，且 cpal 错误类型有破坏性变化，不急着升。

## 6. 验收

- 每一步提交前在 dev-fedora 容器中通过 `cargo fmt --check`、`cargo clippy -D warnings` 和 `cargo test --all-targets --locked`。
- 用户在自己的 kitty 中用隔离的 XDG 目录打开 `~/Music` 确认：
  - 曲库显示 `音频 - …` 原文件名，第二行为 `ASMR(衣鶴) · 衣鹤 · FLAC`；
  - `f` 列出“全部 12”和 6 个文件夹，不含空的 `ASMR`；
  - 筛选后按 `n` 和列表循环都不离开该文件夹；
  - 搜索 `studio_video` 能找到 `涩涩ASMR`；
  - 默认“播完停止”，录音播完后停止并提示；
  - `playerctl metadata title` 显示文件名，`playerctl loop None` 不会把“播完停止”改成“顺序”；
  - Whisper 字幕照常随播放滚动。
- 改名验证使用复制到临时目录的文件，不改动 `~/Music`。
